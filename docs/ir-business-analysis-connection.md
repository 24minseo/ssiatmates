# IR 사업 내용 입력·분석 연결

확정된 입력 → 분석 대기 → 7개 항목 확인 구간을 기존 Supabase/n8n 백엔드에 연결합니다.
디자인 선택 이후 HTML 생성·이미지 편집·다운로드 연결은 이 변경에 포함하지 않습니다.

## 호출 흐름

브라우저는 로그인한 사용자의 Supabase 세션으로 Edge Function을 호출합니다.
n8n URL, DeepSeek 키, Supabase 서비스 키를 브라우저에 전달하지 않습니다.

1. 텍스트는 100~100,000자, PDF는 10MB 이하로 검사합니다. 두 입력의 동시 제출은 허용하지 않습니다.
2. `ir-deck-api-v1 / prepare_input`에 전체 텍스트 또는 PDF 메타데이터를 보냅니다.
3. PDF는 파일 SHA256과 실제 `%PDF-` 서명을 확인하고, 비공개 `ir-deck-assets` 버킷의 서명 업로드를 사용합니다.
4. `confirm_pdf`로 서버 확인 후 `request_generation`으로 기존 분석 워크플로우를 실행합니다.
5. `get_job`을 중복 없이 조회하고 실제 완료된 뒤에만 확인 버튼을 활성화합니다.
6. `get_preview`의 제목과 `ir-deck-studio-v2 / get_business`의 전체 본문을 함께 표시합니다.
   전체 본문에는 기존 추가 분석 내용도 포함되며 브라우저 정규식으로 재분류하지 않습니다.
7. 디자인 단계로 이동하기 전에 `save_business`로 수정 내용을 저장합니다. 실패하면 확인 화면과 입력값을 유지합니다.

## 재시도와 저장

- 입력/접수 UUID를 임시 초안에 보존합니다. 같은 입력의 재시도·새로고침 후 이어가기는 기존 작업을 조회합니다.
- PDF 파일 바이너리와 업로드 토큰은 임시 초안에 저장하지 않습니다. 업로드를 마치지 못했다면 같은 파일을 다시 선택합니다.
- 업로드 응답 유실 시 `confirm_pdf`로 실제 저장 여부를 확인합니다.
- 저장 응답 유실 시 같은 저장 ID와 같은 내용으로 먼저 재확인한 뒤 후속 수정값을 저장합니다.
- 다른 화면의 수정과 충돌하면 서버 버전 검사를 적용하며 사용자 입력을 덮어쓰지 않습니다.
- 숨겨진 탭은 조회를 쉬고, 화면을 나가면 조회를 중단합니다. 서버에 접수한 AI 호출 자체를 취소하지는 않습니다.
- 로컬 초안의 기존 분석은 로그인 사용자 ID가 일치할 때만 이어갑니다.

기존 확인용 초안 API는 항목별 `body`만 저장하므로, 이 화면에서 수정한 제목과 본문을
`# 제목\n\n본문` 형태의 일반 Markdown으로 저장합니다. 읽을 때 두 필드를 복원합니다.
이는 이후 HTML 생성에 전달되는 확인 내용에도 그대로 포함됩니다.

## 검증

- `node scripts/check-ir-analysis.mjs`: 입력 전체 전달, PDF 검사/업로드 응답 유실, 제목·본문 저장 복원, 다른 작업 응답/오래된 저장 거부
- 새 모듈 ESLint, 변경 구간 타입 검사, Vercel 빌드 통과
- 로컬 실제 Chrome + 모의 API: PDF/텍스트 입력, 완료 전 확인 차단, 전체 본문 표시, 수정 저장, 저장 실패 시 입력 유지/재시도, 새로고침 후 중복 접수 없이 이어가기
- 실제 배포된 두 Edge Function의 production origin CORS 사전 요청 확인

저장소 전체 TypeScript 검사는 기존 오류 224개에서 223개로 줄었고 새 진단은 없습니다.
전체 lint에는 기존 포맷/타입 규칙 오류 및 로컬 빌드 산출물 오류가 남아 있어 전체 통과로 표기하지 않습니다.
입력·분석 브라우저 검증은 모의 API로 수행했으므로, 실제 로그인 계정과 n8n/AI의 통합 실행은 별도 확인이 필요합니다.
