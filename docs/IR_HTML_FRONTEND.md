# IR 덱 HTML 생성 화면 연결

디자인 선택의 **이 디자인으로 IR 덱 만들기**는 `ir-deck-html-api-v1`의 실제 생성 작업을 요청한다. 분석 내용을 고정 텍스트 상자에 복사하던 편집 경로는 제거했다. 최근 파일에는 문서/작업 ID를 저장하며, HTML 및 이미지 서명 URL은 브라우저 저장소에 저장하지 않는다.

## 사용자 흐름

1. PDF 업로드 → 기존 `ir-deck-api-v1` 분석 → 사업내용 확인 화면으로 자동 이동한다.
2. 확인·수정한 사업내용을 `ir-deck-studio-v2`에 저장한다.
3. 색상 1~2개, light/dark, 글꼴을 선택한다. 브랜드 설정과 사업내용의 저장 버전을 지정해 HTML 생성을 요청한다.
4. 전체 원문과 확인 내용을 읽는 기존 HTML 생성 워커가 7장과 문장형 제목·레이아웃을 만든다. 프론트가 제목/본문을 다시 조립하지 않는다.
5. `queued → planning → generating → validating → ready`를 조회한다. 완료된 보안·렌더 검사 기록이 있는 문서만 표시한다.
6. 이미지 슬롯을 클릭해 PNG/JPG를 업로드하거나, **이미지 추가** 후 원하는 슬라이드 위치를 클릭한다. 추가 이미지는 위치·크기·앞뒤 순서·contain/cover를 바꿔 저장할 수 있다. 생성된 슬롯의 프레임과 배치는 유지한다.
7. PDF/PPTX는 현재 서버 저장 이미지 버전을 지정해 출력 요청한다. 출력에는 AI를 다시 호출하지 않는다. 준비된 다운로드 링크는 5분간 유효하며, 만료 시 재발급한다.

PPTX는 7장의 슬라이드 이미지를 담은 파일이다. PowerPoint에서 텍스트·도형을 개별 편집하는 출력은 지원하지 않는다. 빈 이미지 슬롯은 출력 시 업로드 안내를 숨기고 기존 공간을 유지한다.

## API와 저장

- 인증은 기존 Supabase 사용자 세션을 사용한다. 프론트에 service role key, n8n 웹훅 또는 렌더 서버 비밀값을 전달하지 않는다.
- 생성 요청 번호를 네트워크 요청 전에 저장한다. 응답 유실 후 재확인과 새로고침은 같은 요청 번호/입력 버전을 사용한다.
- 이미지는 기존 private `ir-deck-editor-assets-v2` 버킷에 서명 업로드한 뒤 서버 해시 확인을 거친다.
- 이미지 연결은 `save_slot_image` / `save_user_image`, 출력은 `request_export` / `get_export` / `get_export_download`를 사용한다. 전역 이미지 버전으로 동시 수정 충돌을 감지한다.
- 이미지 저장 응답이 불확실하면 같은 변경으로 저장을 재확인하거나 서버 최신값을 불러올 수 있다. 검증 실패를 정상 생성으로 표시하지 않는다.
- 이미지 주소는 4분마다 갱신한다. 생성 상태는 3초마다 조회하며 숨겨진 탭은 조회를 미룬다. 별도 스케줄 트리거는 필요 없다.
- HTML은 `allow-same-origin` 없는 sandbox iframe에서 표시한다. 생성된 스크립트/이벤트/외부 주소를 제거하고 CSP를 적용한다. 이미지 클릭에 필요한 앱 자체 스크립트만 nonce로 허용하며 iframe 출처·창·채널을 함께 확인한다.

## 검증

`node scripts/check-ir-html-frontend.mjs`: 요청 재사용, 브랜드 버전, 검사된 7장 문서, 서명 URL, 이미지 배치 범위의 5개 테스트.

로컬 브라우저 + 모의 API로 PDF 업로드, 분석 완료 자동 이동, 사업내용 수정 저장, 실제 HTML 미리보기, 생성 응답 실패 후 동일 요청 재확인, 새로고침 후 재개, 생성/사용자 이미지 저장, 위치 변경, 최신 이미지 버전의 PDF 출력 요청을 확인했다. 테스트에서 넣은 생성 HTML 스크립트/이벤트는 실행되지 않았다.

Vercel production 빌드와 새 모듈 ESLint를 확인했다. 전체 저장소 lint와 TypeScript에는 기존 오류가 있어 전체 통과로 보고하지 않는다. 실제 계정의 n8n·DeepSeek 생성 시간과 최종 디자인 품질은 배포 후 실제 PDF로 별도 확인해야 한다.
