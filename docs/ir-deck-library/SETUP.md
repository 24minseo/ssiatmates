# 계정별 IR 덱 목록 및 복원

## 설치

1. Supabase SQL Editor에서 `ir-deck-library-install.sql` 전체 실행. `ir_deck_account_library_v1 / ready` 확인.
2. 프론트 목록 연결 코드를 main에 병합하고 Vercel 배포 완료 확인. Edge Function 배포나 n8n 변경은 필요 없다.
3. 같은 Supabase 계정으로 서로 다른 브라우저에 로그인하고 홈 새로고침. 양쪽에서 서버에 저장된 덱을 확인한다.

## 계약

프론트의 기존 Supabase 사용자 세션으로 다음 RPC를 호출한다. 클라이언트가 user_id나 서버 키를 보내지 않는다.

- `list_my_ir_decks_v1`: `auth.uid()`의 덱 메타데이터만 페이지별 조회. 정렬 키는 created_at + deck_id로, 생성 시각이 같아도 다음 페이지가 누락되지 않는다. 목록에 HTML·사업 원문·작업 claim token을 포함하지 않는다.
- `get_my_ir_deck_resume_v1`: 선택한 덱의 사용자 확인본·분석 작업·최신 HTML 작업/문서 번호·브랜드 설정을 읽는다. 완료된 HTML은 get_document로, 진행 중 생성은 get_job으로 기존 컴포넌트에서 이어간다. 복원 자체는 새 생성이나 AI 호출을 하지 않는다.
- `rename_my_ir_deck_v1`: 제목 변경을 서버에 확인한 다음 UI에 반영한다.
- `hide_my_ir_deck_v1`: 해당 계정 목록에서 삭제한다. 원본 파일을 지우는 하드 삭제가 아니므로 기존 생성/출력/이미지 참조를 파괴하지 않는다. 다른 브라우저에서도 다시 목록 조회하면 표시하지 않는다.

## 캐시와 이전 자료

- 서버에 저장된 덱 목록이 기준이다. 브라우저 프로젝트는 deck_id 기준으로 합쳐 중복을 제거한다.
- 새 캐시 키는 `ssiat-ir-deck-workspace-v2:<user_id>`이다. 로그아웃 상태는 guest 키를 사용한다.
- 이전 공통 키는 삭제하거나 덮어쓰지 않는다. 로그인 사용자와 소유자가 일치하는 분석/HTML 참조만 자동으로 가져온다. 소유자를 식별할 수 없는 오래된 공통 초안은 특정 계정에 임의로 올리지 않고 원래 키에 보존한다.
- 현재 계정 캐시에서 작성한 미저장 초안은 유지한다. 그 초안의 파일 자체를 다른 브라우저로 복사하는 기능은 아니다.
- 사용자 확인본에 미저장 변경이 있으면 서버 복원으로 덮어쓰지 않고, 기존 revision 충돌 검사를 통해 저장하도록 한다.
- 홈 진입·브라우저 포커스 복귀·제목 변경/삭제 후 목록을 갱신한다. 실시간 구독이나 정기 n8n 실행을 추가하지 않는다.
- 화면에 가까운 카드부터 썸네일을 읽는다. 모든 HTML을 목록 RPC에 담거나 생성 모델을 다시 호출하지 않는다.

## 확인

브라우저 A에서 덱 생성 → 브라우저 B 같은 계정으로 홈 열기 → 같은 덱 열기 → 제목 변경 후 A로 돌아와 확인 → 삭제 후 양쪽 목록에서 제외 확인. 다른 계정으로 전환해 이전 계정의 카드·원문·진행 화면이 남지 않는지 확인한다.

자동 검증: SQL 소유권·목록·페이지 경계·재설치·복원·제목·삭제 테스트, 클라이언트 목록 병합/복원 테스트, 늦은 계정 응답 및 삭제 이후 오래된 목록 응답 테스트, 타입/빌드 검사.
